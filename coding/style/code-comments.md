# Code Comments

## Do Not

- Avoid comments that explain what something is "not" unless it's actually valuable
- Avoid comments that may be likely to become stale quickly
- Avoid referencing issues, ticket-numbers, milestones for no reason as they are part of the git history

## Executing Code

- Use code comments sparsely
- Only highlight unexpected or non-obvious parts that the code itself does not explain by itself

## Testing Code

- Tests should be structured and use comments to separate blocks for readability `// given`, `// when`, `// then`.
